# IOCS / FCSリファレンス

PC-E500 の ROM 8.5 を解析して得た IOCS/FCS の入口表と、Sharp *Technical Reference Manual* の公開 ABI をまとめたもの。ここでいう「入口」は ROM 上の実装アドレスであり、個々のコマンドの完全な引数・返却値仕様ではない。未記載のレジスタ破壊規則やエラー番号を推測して利用しないこと。

## 最初に: IOCS の使い方

IOCS はデバイスを統一的に操作するディスパッチャである。呼出し前に内部 RAM のデバイス番号とドライブ番号、`IL` のコマンド番号を設定し、公開ベクタ `FFFE8h` を `CALLF` する。呼出し先を直接 `CALLF E0000h` に固定せず、互換性のため公開ベクタを用いる。

```asm
; 1. 対象を選ぶ: LCD/画面デバイス 0、ドライブ 0
MV   ($D6),$00                ; device
MV   ($D7),$00                ; drive

; 2. 処理を選ぶ: 指定位置へ 1 文字表示
MV   IL,$41                   ; command
MV   ($D4),$00                ; x 座標 (bl)
MV   ($D5),$03                ; y 座標 (bh)
MV   A,$41                    ; 個別コマンドの引数: 'A'

; 3. 実行し、carry と A を確認する
CALLF $FFFE8
```

`D6h`/`D7h` は CPU レジスタではなく内部 RAM の番地を表す。個別コマンドが使用する A/BA/I/X/Y、内部 RAM、返却値はデバイスごとに異なる。上の `41h` は device 0 の場合だけ「指定位置へ 1 文字表示」であり、同じ番号でも別デバイスでは別機能になり得る。座標は内部 RAM `D4h`(x)/`D5h`(y) で渡す（技術資料の (bl)/(bh)）。

### 結果の確認と注意

- 原則として成功は carry clear、失敗は carry set と A のエラー値で返る。実際に使うコマンドのエラー値・副作用は技術資料の個別ドライバ仕様で確認する。
- `08h`–`0Fh`、`10h`–`1Fh`、`20h`–`3Fh` は file-control 用の標準領域である。ファイルや媒体を扱わない実験では、`3Fh`（format）や書込み系を呼ばない。
- 同じドライブ名を持つ IOCS ヘッダが追加された場合、後から組み込まれたデバイスが選ばれる。周辺機器のドライバ追加後は、表中の ROM 固定アドレスではなく実行時ヘッダを基準にする。

## 呼出し入口

| 種別 | 公開ベクタ | 実体 (ROM 8.5) | 用途 |
|---|---:|---:|---|
| IOCS | `CALLF FFFE8h` | `JPF E0000h` | デバイス IOCS の選択と実行 |
| FCS | `CALLF FFFE4h` | `JPF E06BFh` | ファイル制御の共通処理 |

### 選択値

| 項目 | 設定場所 | 意味 |
|---|---|---|
| device | 内部 RAM `D6h` | IOCS ヘッダのデバイス番号 |
| drive | 内部 RAM `D7h` | そのデバイス内のドライブ番号 |
| command | `IL` | 実行する IOCS コマンド |

コマンド番号の区分は次のとおり。`00h`–`07h` は IOCS 主処理用で、各デバイスのエントリには飛ばない。`40h` は全デバイス共通の初期化、`41h`–`7Fh` はデバイス固有、`80h`–`FFh` は予約である。

| 範囲 | 区分 |
|---|---|
| `08h`–`0Fh` | 標準キャラクタデバイスの file-control |
| `10h`–`1Fh` | 標準ブロックデバイスの file-control |
| `20h`–`3Fh` | 特殊デバイスの file-control |
| `3Fh` | format |
| `40h` | 初期化 |
| `41h`–`7Fh` | デバイス固有処理 |

## ROM 8.5のIOCSヘッダ

## ROM 8.5のIOCSヘッダ

ヘッダ形式は `[next:3][device:1][attribute:1][entry:3][NUL終端ドライブ名]`。実行時の `BFCA2h` は `DF820h` を指した。

| header | next | device | attr | entry | drive names |
|---|---|---|---|---|---|
| `DF820h` | `DF833h` | 0 | A2h | `F223Fh` | STDO:SCRN: |
| `DF833h` | `DF846h` | 1 | A1h | `F16F5h` | STDI:KYBD: |
| `DF846h` | `DF853h` | 2 | D3h | `EAA86h` | COM: |
| `DF853h` | `DF865h` | 3 | A2h | `EA4B3h` | STDL:PRN: |
| `DF865h` | `DF872h` | 4 | D7h | `E96DEh` | CAS: |
| `DF872h` | `DF884h` | 6 | C3h | `F0000h` | S1:S2:S3: |
| `DF884h` | `DF893h` | 5 | 83h | `E493Ah` | E:F:G: |
| `DF893h` | `DF89Ch` | 9 | 00h | `EF03Eh` | (なし) |
| `DF89Ch` | `DF8A9h` | 7 | 00h | `EB681h` | X:Y: |
| `DF8A9h` | `FFFFFh` | 8 | 00h | `E0183h` | SYSTM: |


属性bitは bit7=file-control可、bit6=特殊ファイル、bit5=block/character、bit4=ASCII既定、bit2=同時read/write不可、bit1=write、bit0=read。G:はdevice 5のdrive 2、S3:はdevice 6のdrive 2。

## 選択例

```asm
; LCDの指定位置に1文字を出す例（device 0, command 41h）。
; D7h は画面デバイスでのドライブ選択を明示するため 0 にする。
MV   ($D6),$00
MV   ($D7),$00
MV   ($D4),x                  ; x 座標
MV   ($D5),y                  ; y 座標
MV   IL,$41
; A = character code
CALLF $FFFE8

; G: を示す RAM ディスクドライバ選択。実行する file-control
; command とその引数は No.05 の個別仕様に従う。
MV   ($D6),$05
MV   ($D7),$02
; IL = command
CALLF $FFFE8
```

技術資料の「No.05 RAM Disk Driver (E: F: G:)」とROMヘッダは一致する。ROM内G:データはRAM領域ではなく本体ROM `C0018h-DFFFFh` に焼かれているが、IOCSからは同じdevice 5として扱われる。

## 根拠と更新方針

- 公開 ABI、ヘッダ構造、属性ビット、デバイス番号、コマンド番号の区分は Sharp *Technical Reference Manual PC-E500* の Chapter 2 *Outline of IOCS*（印刷ページ 15–17）による。
- 下表のヘッダ値・コマンド入口は ROM 8.5 からの抽出結果による。周辺機器が追加した実行時ヘッダは含まれない。
- 「名称未確定」は入口アドレスのみ確定している。仕様を補う際は推測で名称を埋めず、技術資料または実機トレースを根拠として更新する。
