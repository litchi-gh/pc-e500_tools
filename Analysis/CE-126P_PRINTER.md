# CE-126P プリンタ（11ピン）の通信手順

PC-E500 の ROM（`Emulator/app/rom/PC-E500.rom`、256KB、C0000h〜FFFFFh）のプリンタ・ドライバを逆アセンブルして読んだ結果。
エミュレータや ESP32S3 版で CE-126P を再現し、USB のサーマルプリンタへ出すための仕様としてまとめる。

- 「確認済み」は ROM のコードから読めたもの、または [codaris/SharpManager](https://github.com/codaris/SharpManager)（Arduino で CE-126P を再現する実装）と一致したもの。
- 「未確認」は推定。実機かエミュレータで確かめるまで、これを前提にしない。

## 1. この ROM での入口

IOCS のデバイス 3（`STDL:PRN:`）。ヘッダは `DF853h`、入口は **`EA79Dh`**。

> [IOCS_REFERENCE.md](IOCS_REFERENCE.md) の「ROM 8.5」の表は入口を `EA4B3h` としているが、この ROM では `EA79Dh` だった（デバイス 0 も `F223Fh` ではなく `F2949h`）。版が違うので、あの表の番地はこの ROM には当てはまらない。

コマンドの表（16 ビットの表。上位は `E`）。08h〜0Eh は `EA7BBh` から、3Fh〜43h は `EA7C9h` から並ぶ:

| cmd | 機能 | 入口 | 内容 |
|---|---|---|---|
| 08h | OPEN | `EA7D6h` | プリンタの有無を調べる（`EA907h`） |
| 09h | CLOSE | `EA7DEh` | 行の途中なら印字する |
| 0Ah, 0Ch, 0Eh | 読み出し | `EA7D2h` | エラー 0Ah |
| 0Bh | ブロック書込み | `EA7E3h` | 1 バイト書込みを Y 回 |
| 0Dh | 1 バイト書込み | `EA7E7h` → `EA93Ah` | 5 節 |
| 3Fh | フォーマット | `EA899h` | 端子の初期化だけ |
| 40h | 初期化 | `EA882h` | 端子の初期化 → プリンタの有無を調べる |
| 41h | 印字 | `EA93Ah` | 1 文字（0Dh と同じ処理） |
| 42h | 印字位置 | `EA7EFh` | A = いまの桁 |
| 43h | プリンタチェック | `EA80Ch` | なしなら A=54h でエラー。CE-126P なら I=24（桁数）, A=0 |

## 2. プリンタの種類（`BFD1Dh`）

OPEN のときの確認（`EA907h`）で決まる。

| 値 | 意味 | 状態 |
|---|---|---|
| 00h | プリンタなし | 確認済み |
| 02h | **CE-126P**（1 行 24 桁、11 ピン） | 確認済み |
| 80h | 別の出力先（`EADC0h` へ送る。シリアルのプリンタか） | 未確認 |
| 04h | 別の機種の行の扱い（`EAA50h`） | 未確認 |

`BFD1Dh` の bit7 が立っていなければ、11 ピンで CE-126P を探す（`EAB45h`）。応答があれば 02h、なければ 00h。

CE-126P のときの作業領域（`(E6h)` が指す先）:

| 位置 | 内容 |
|---|---|
| `+2Dh` | いまの桁（0〜） |
| `+2Eh` | 最後の桁 = 17h（24 桁） |
| `+2Fh` | 直前の文字 |
| `BFD1Eh` bit6 | CR を受け取って、まだ行を出していない |

## 3. 信号と E-PORT の対応（確認済み）

| 信号 | 向き | E-PORT | 11 ピンの番号（SharpManager の表） |
|---|---|---|---|
| BUSY | PC → 機器 | `F3h`（EOL）bit6 | 4 |
| DOUT | PC → 機器 | `F4h`（EOH）bit2 | 5 |
| XOUT | PC → 機器 | `FDh`（SCR）bit4〜6 = 001b で High | 7 |
| ACK | 機器 → PC | `F5h`（EIL）bit7 | 9 |
| DIN | 機器 → PC | `F6h`（EIH）bit7 | 8 |

GND は 3 番。CE-126P は DIN を動かさない（SharpManager も入力のまま）。

## 4. 通信の手順

すべて **1 ビットずつ、下位ビットから**、DOUT で送る。CE-140F のような 4 ビットずつの転送は使わない。

### 4.1 デバイスコード（XOUT = High）: `EABDEh`

1. XOUT を High にする。
2. ACK が High になるのを待つ。来なければ待ち時間（`EAC56h`）をはさんで最大 6 回見る。来なければ「機器なし」（carry あり、A=0）。
3. 8 ビットを下位から:
   1. DOUT にビットを出す
   2. ACK が **High** になるまで待つ
   3. BUSY を High にする
   4. ACK が **Low** になるまで待つ
   5. BUSY を Low にする
4. BUSY・DOUT を Low、XOUT を止め、待ち時間 ×4。

機器の側は：XOUT が High になったら ACK を High にする。BUSY が High になったら DOUT を読んで ACK を Low、BUSY が Low になったら次のために ACK を High。

### 4.2 データの 1 バイト（XOUT = Low）: `EAB8Eh`

8 ビットを下位から:

1. DOUT にビットを出す
2. ACK が **Low** になるまで待つ
3. 割り込みを止め、BUSY を High にする
4. ACK が **High** になるまで待つ
5. 割り込みを戻し、BUSY を Low にする

8 ビットのあと DIN（`F6h` bit7）を見る。High ならエラー（A=0）。

機器の側は：BUSY が High になったら DOUT を読んで ACK を High、BUSY が Low になったら ACK を Low。
4.1 とは ACK の向きが逆になる点に注意。

ACK を待つ処理（`EAC98h`・`EACCAh`）は 0D4C0h 回まで見て、その間 BREAK を見る（`BFCBEh` の bit7・bit6）。時間切れか BREAK でエラー。

### 4.3 決まった並び

| 処理 | 入口 | 送るもの |
|---|---|---|
| プリンタの有無を調べる | `EAB45h` | デバイスコード **0Fh** → デバイスコード **20h** → データ **0Fh** → 待ち ×4 |
| 1 行を印字する | `EAA0Dh` | 残りの桁を空白で埋める → デバイスコード **20h** → データ **24 バイト**（いつも 24 桁ぶん） → データ **0Dh** → ACK が Low になるまで待つ（印字が終わるのを待つ） → 待ち ×2 → データ **0Eh** |
| その他 | `EAB84h` / `EAB88h` | デバイスコード 10h / 00h（呼ぶ側は未確認。カセットのモーターか） |

デバイスコードの意味（0Fh・20h・10h・00h が何を選ぶか）は ROM の使われ方からの推定で、CE-126P 側の資料では確かめていない。SharpManager は 0Fh・10h のあとに 9ms の ACK を返すが、20h・00h には返さない。ROM はデバイスコードを送ったあとの ACK を見ないので、どちらでも動く。

## 5. 文字の扱い（`EA93Ah`、`EA9C9h`）

### 改行

| 入力 | 動き |
|---|---|
| CR（0Dh） | 印を立てるだけ |
| CR の次に LF（0Ah） | 行を印字する |
| CR の次に LF 以外 | 空白を 1 つ置いてから、その文字を扱う |
| CR のない LF | 空白として置く |
| 24 桁を超えた | 自動で行を印字し、次の行へ |

### 文字コードの変換（PC-E500 → CE-126P）

| PC-E500 の文字 | 送るコード |
|---|---|
| 00h〜1Fh、7Fh | 20h（空白） |
| `0`（30h） | F0h |
| `O`（4Fh） | 30h |
| 20h〜7Eh（上の 2 つ以外） | そのまま |
| 80h〜9Fh | 20h |
| A0h〜DFh（カナ） | そのまま |
| E0h〜E7h | 20h |
| E8h〜EBh | +0Dh（F5h〜F8h） |
| ECh〜F0h | 20h |
| F1h | F4h |
| F2h〜F4h | −1（F1h〜F3h） |
| F5h〜FFh | 20h |

`0` と `O` の入れ替えは SharpManager と一致する（受けた 30h を `O`、F0h を `0` に戻している）。CE-126P の文字表では 30h が `O` の形、F0h が `0` の形と考えられる。

**再現するときは、この表の逆を引いて PC-E500 の文字に戻し、PC-E500 のフォント（[CHARACTER_FONT.md](CHARACTER_FONT.md)）で画像にする**のが簡単。E8h〜EBh・F1h〜F4h の記号が CE-126P でどの形になるかは未確認。

## 6. 再現する機器の最小の動き

1. XOUT が High → デバイスコードを 4.1 の向きで受ける。
2. 0Fh・20h を受けたら「選ばれた」とする（CE-140F の 41h とは別）。
3. XOUT が Low の間は 4.2 の向きでバイトを受ける。
4. 0Dh を受けたら、ためた 24 バイトを 1 行として出す。印字のあいだは ACK を High にしておけば、PC は待つ（4.3）。
5. 0Eh・単独の 0Fh（有無の確認）は印字せず、そこで選択を終える（次のデバイスコードまで BUSY には応じない）。
6. DIN は Low のまま。

同じ線に CE-140F（デバイスコード 41h）がつながっていても、ACK は「どれかが High なら High」（ワイヤード OR）なので共存できる。

## 根拠

- ROM の逆アセンブル：`EA79Dh`〜`EAD50h`、`EC5A0h`〜`EC5C6h`（`DisAssembler/app/e500dasm.exe`、入口ごとに切り出して確認）。
- [codaris/SharpManager](https://github.com/codaris/SharpManager) の `Arduino/Sharp.h`・`Sharp.ino`・`Arduino.ino`：端子の番号、ビットの順番、ACK と BUSY の向き、30h/F0h の入れ替え。
- PockEmul の `ce126.cpp` は取得できなかった（GitHub で 404）。
- 6 節の動きをエミュレータ（`Emulator/src/native/ce126p.cpp`）に実装し、ROM をそのまま動かして確かめた：`LPRINT`・`LLIST` が印字される、24 桁で折り返す、`0`/`O` が戻る、カナ（B1h）がそのまま通る、BEEP では選ばれない、CE-140F と同じ線で両方動く、外すと `Printer error`。
