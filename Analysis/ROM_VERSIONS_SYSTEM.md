# PC-E500 シリーズ ROM 版ごとの違い：E0000h〜E4FFFh・F0000h〜F4FFFh 帯（IOCS・FCS・表示・キー入力・行エディタ）

手元の ROM イメージ 11 本（`Emulator/app/rom/`）のうち、IOCS・FCS・RAM ディスクなどの装置処理（E0000h〜E4FFFh）と、リセット・割込み・表示・キー入力・行エディタ（F0000h〜F4FFFh）を比べ、違いをまとめたもの。F4xxxh 帯にある BASIC のトークン化の変更は [ROM_VERSIONS_BASIC.md](ROM_VERSIONS_BASIC.md) で扱い、ここでは番号だけ示す。装置ドライバ（E8000h〜EBFFFh）は [ROM_VERSIONS_DRIVERS.md](ROM_VERSIONS_DRIVERS.md)。版番号の読み方（上位桁＝改訂、下位桁＝機種コード）と ROM の一覧は [ROM_VERSIONS_BASIC.md](ROM_VERSIONS_BASIC.md) §1 を参照。

## 確度の表し方

| 表記 | 意味 |
|---|---|
| **実験** | エミュレータ（`Emulator/bin/e500core.dll`）上で全 ROM に同じ操作をして違いを確かめた |
| **コード** | 逆アセンブル・データの比較で違いを確かめた。挙動は試していない |
| **推定** | コードの形から目的を推し量ったもの |

### 1.1 IOCS ヘッダ

全 11 本とも同じ 10 装置（SCRN・KYBD・COM・PRN・CAS・S1:S2:S3:・E:F:G:・device 9・X:Y:・SYSTM）を、同じ順で連結している。違うのはヘッダ表の置き場所と各入口の番地だけである。

| 版 | ヘッダ先頭 |
|---|---|
| 2.1 | `E02A6h`（128 KB の ROM で、下位の RAMFILE 領域がない） |
| 2.2、3.2、5.3、6.3、6.2、7.2、7.5、8.5 | `DF820h` |
| 6.4、8.4 | `DF500h` |

確度: コード。

## 2. 改訂ごとの変更

改訂 5→6、6→7 では、この帯に機能の変更はない（コードのずれに伴う表の再配置だけ）。E0000h〜E4FFFh の IOCS・FCS・RAM ディスクは、改訂 2〜7 を通じて同じ機種の中では変わっていない。

### 2.1 改訂 2 → 3（2.2 → 3.2）

番地は 3.2 のもの。

| # | 対象 | 番地 | 変更 | 確度 |
|---|---|---|---|---|
| 1 | キー走査 | `F1F3Fh`〜`F1F4Ch` | 読み取ったキー入力（`(BP+4)`）を、行番号 `(BP+0)` で引く RAM の表 `[BFCA5h+行]` と AND する処理を追加。行ごとに特定のキーを無効にできるようにしたものと見られる（推定） | コード |
| 2 | キー走査 | `F1E50h`、`F1F0Bh` | `($EA)` bit3 を見る位置を移動。旧版は `(BP+PX)` が 03h で、かつ `($EA)` bit3 が立っているときだけ `[BFCBEh]` bit7 を立てていた。新版は `($EA)` の条件を外し、`($FF)` bit3 を見る経路（`F1F0Bh`）の側で `($EA)` bit3 を判定する | コード |
| 3 | 行エディタ | `F39D6h`、`F39DEh` | AER 側の処理 `CALLF E5214h` を呼ぶ前に BP を切り替え（`PMDF ($EC),D6h`）、戻った後に元へ戻す（`PMDF ($EC),2Ah`）処理を追加 | コード |
| 4 | 行エディタ | `F3E9Ah` | `CALL F6114h` の戻り値を `(BP+0)` にも保存する命令を追加 | コード |
| 5 | 行エディタ | `F384Ch`、`F4712h` | カーソルを消す呼出し（`A=0`、`IL=45h` で SCRN:45）を共通の小関数 `F4712h` にまとめ、`F384Ch` に呼出しを追加 | コード |
| 6 | トークン化 | `F4DDBh` | ELSE の判定（[ROM_VERSIONS_BASIC.md](ROM_VERSIONS_BASIC.md) §3.1 #6） | 実験 |

### 2.2 改訂 3 → 5（3.2 → 5.3）

5.3 は機種コードも違うため、差の大半は機種差（§3.1）である。改訂 5 以降の全機種に入っている変更は次の 2 件。

| # | 対象 | 番地 | 変更 | 確度 |
|---|---|---|---|---|
| 1 | 行エディタ | 3.2 の `F3D52h` | 空白詰めのループ回数 0 の対策（[ROM_VERSIONS_BASIC.md](ROM_VERSIONS_BASIC.md) §3.2 #1） | コード |
| 2 | 行エディタ | 3.2 の `F3726h` | U スタックを 0FFh 下げる処理の前に BP の切り替え（`PMDF ($EC),D4h`）を移動 | コード |

### 2.3 改訂 7 → 8（7.5 → 8.5、6.4 → 8.4）

機種コード 4 と 5 の両方に同じ変更が入っている。番地は 8.5 のもの（括弧内は 7.5）。

| # | 対象 | 番地 | 変更 | 確度 |
|---|---|---|---|---|
| 1 | フォント・表示の表 | `F2528h`、`F24B8h`、`F25EDh`〜`F25FFh`、`F2BFBh` ほか | フォント（6×8 ドット 256 文字）と、カーソル・記号などの表を拡張 ROM（`30000h`〜`3098Eh`）へ移し、参照先を書き換えた（フォント本体は `F21A5h` → `30000h`）。字形は変わっていない（§3.1） | コード |
| 2 | キー対応表 | `F1987h`〜`F19B7h`、`E1F5Fh`、`F2D55h` | キーコードの対応表（`F2865h`、`F3472h`〜`F365Ch`）を拡張 ROM（`306C0h`、`307A4h`〜`3098Eh`）へ移した | コード |
| 3 | 行エディタ | `F2D55h`〜（`F3456h`〜） | BP 相対の作業領域を 1 バイト広げ、以降の項目を 1 つずつずらした。キーコードの 2 バイト目 1Ch〜1Fh、3Eh・3Fh などへの分岐と、拡張 ROM・末尾パッチ域（`FFA63h`、`FFB84h`、`FFBF6h`）への呼出しを追加。新しい編集キーへの対応と見られる（推定） | コード |
| 4 | 行エディタ | `F361Bh`〜`F3B60h` | #3 に合わせて BP の切り替え値と作業領域の位置を 1 ずつずらした | コード |
| 5 | リセット | `F10E4h`〜`F114Ah` | 起動時に 3 回に分けてキー行列を走査し、特定の 2 つのキーだけが押されているとき `($D8)` bit1 を立てる処理を追加 | コード |
| 6 | キーボード初期化 | `F16B7h`〜`F16D6h` | #5 の bit1 が立っていれば、IOCS を呼んだ後に拡張 ROM の `314AEh` を `($FB)=83h` で呼ぶ | コード |
| 7 | 割込み | `F21AFh` | 待ち（`MV I,0481h` / `WAIT`）を追加 | コード |

#5・#6 は、リセット時のキー操作で入る診断メニューである。判定は「KO0 の KI6（SHIFT）と KO4 の KI4（`,`）だけが押され、他の行には何も押されていない」ことである。入り方と中身は §2.4。

### 2.4 診断メニュー（Diag Menu）

§2.3 の #5・#6 で入るサービス用のメニュー。番地は 8.5 のもの。エミュレータで確かめたが、実機では試していない。

**入り方**: SHIFT と `,` の 2 つだけを押したまま RESET し、メニューが出たら離す（実験）。ON は押さない。ON を押していると、キーの判定に進む前に `($D8)` が 0 になる（`F1151h`、コード）。

| 条件 | 結果 | 確度 |
|---|---|---|
| 8.5（PC-E650）、8.4（PC-U6000） | メニューが開く | 実験 |
| 7.5（PC-E550） | 通常の `MAIN MENU` が出る | 実験 |
| SHIFT だけ、`,` だけ、ほかのキーも一緒に押す（`A`、`SPACE` で確認） | 入らない（8.5） | 実験 |
| 内蔵 RAM が未初期化 | 初期化の画面が出る。PF1 で初期化すると `MAIN MENU` になる。初期化の後でやり直す（8.5） | 実験 |

**抜け方**: RESET だけである。メニューのループ（`314C7h`）に出口はなく（コード）、CCE はメニューに戻るだけである（実験）。

エミュレータでは、`e500_reset` がキーの状態を消す（`Emulator/src/native/machine.cpp`）。キーは `e500_reset` の呼出し後、`e500_run` の前に押す。呼出し前に押しても入らない（実験）。

**メニューの項目**: キーと飛び先の表は `3156Ah`（キーコード）と `314DEh`（番地）にある。

| 2 | `LB` | `31A22h` | 低電圧の確認と見られる（`Low Battery check` の文字列がある） | 未確認 | 推定 |
| 3 | `aging1` | `31941h` | LCD、ROM、RAM のチェックを繰り返す | RAM チェックを含むので消える | コード |
| 4 | `aging2` | `3194Dh` | `aging1` と同じ処理を、`($D4)` の初期値を変えて呼ぶ | 同上 | コード |
| 5 | `RAM` | `31AA6h` | RAM に書き、読み直し、1 分待ってまた読み直す（`RAM WRITING`、`RAM VERIFYING`、`1 minute WAIT`） | 書き換える | コード |

**`check list 2`**:

|---|---|---|---|
| 1 | `LCD check` | BASIC プログラムは残った | 実験 |

| 3 | `RAM check` | **消える**。この後に RESET すると `S1(ﾅｲｿﾞｳ):ｱﾀﾗｼｲ ｶｰﾄﾞ ﾃﾞｽ` と出て、PF1 で初期化するとプログラムは残っていない | 実験 |

|---|---|---|

## 3. 機種による違い

### 3.1 フォント（機種コード 3）

6×8 ドットのフォント 256 文字は、5.3・6.3（機種コード 3）を除く 9 本で 1 ドットも違わない。PC-1480U（2.1）、PC-1490UII（6.4）、PC-U6000（8.4）も PC-E500 と同じで、円記号・カナ・グラフィック記号を持つ（3 機種とも画面・カナ入力・添付ソフトが日本語で、国内向けと見られる。[ROM_VERSIONS_MODELS.md](ROM_VERSIONS_MODELS.md) §1）。

5.3・6.3 は 5Ch と 7Fh〜FEh の字形が違う。5Ch は `\`（他の機種は `¥`）、80h 以降はアクセント付きのラテン文字、通貨記号、罫線、ギリシャ文字などで、IBM PC のコードページ 437 と同じ配置の欧文の文字セットである（`CHR$(128)`=Ç、`CHR$(165)`=Ñ、`CHR$(177)`=▒、`CHR$(225)`=ß を表示で確認、実験）。カナはなく、KANA キーを押しても `0` が入力されるだけでカナ入力にならない（実験）。

| 版 | フォント本体 | 違う文字 |
|---|---|---|
| 2.1 | `F20F6h` | なし |
| 2.2 | `F2198h` | なし |
| 3.2、6.2、7.2、7.5 | `F21A5h` | なし |
| 5.3、6.3 | `F2155h` | 5Ch、7Fh〜FEh |
| 6.4 | `F21D5h` | なし |
| 8.4、8.5 | 拡張 ROM `30000h` | なし |

フォントのポインタ表（`BFC84h` へ写す 6 個の 20 bit 番地、[CHARACTER_FONT.md](CHARACTER_FONT.md)）は全版で同じ構成で、番地のずれだけが違う。確度: コード（字形データの比較）。

### 3.2 画面の文言（機種コード 3）

5.3・6.3 は画面の文言が英語で、他の 9 本はカナである。PC-1480U・PC-1490UII・PC-U6000 もカナで表示する。

| 場面 | 5.3・6.3 | その他 |
|---|---|---|
| 電源投入時（RAM カードの初期化待ち） | `S1(MAIN):NEW CARD` / `PF1 --- INITIALIZE` | `S1(ﾅｲｿﾞｳ):ｱﾀﾗｼｲ ｶｰﾄﾞ ﾃﾞｽ` / `PF1 ｼｮｷｶ ｼﾏｽ` |
| 初期化の確認（3.2 `E33BBh` が表示） | `INITIALIZE OK? (Y/N)` | `ｼｮｷｶ OK? (Y/N)` |
| G: ドライブの表示（3.2 `E4EF2h`〜が表示） | ` ENGINEER SOFTWARE ` | ` ｴﾝｼﾞﾆｱ ｿﾌﾄｳｴｱ `（機種コード 1・4 にはこの文字列がない） |

文字列の長さが違うため、表示処理に渡す長さ（3.2 `E33BBh` の Y、`E4EF6h` の Y）と表示位置（`E33C1h`）も機種コード 3 だけ違う。確度: 電源投入時の画面は実験（2.1、3.2、5.3、6.3、6.4、8.4、8.5 で確認）、他はコード。

### 3.3 キー入力（機種コード 3・4）

| 機種 | 違い | 確度 |
|---|---|---|
| 機種コード 3 | キーボードの文字読み出し（KYBD:0Ah・0Ch・0Eh、3.2 の `F1B48h`〜）を、末尾のパッチ域（5.3 `FFF3Ah`、6.3 `FFF4Ah`）の短い処理に置き換え、元の場所を `NOP` で埋めている。置き換え後は、特別なキーコード（0700h）の処理と `[BFC99h]` bit1 による分岐（`F6292h` / `F635Dh`、`F788Ah`）を通らない。カナ入力などの国内向けの処理を外したものと見られる（推定） | コード |
| 機種コード 3 | キーコードの定数（3.2 `F0C84h`〜`F0CEAh` の `A`・`IL` の値）が違う。`5Ch` を返す箇所がある（5.3 の `F0CBEh`）など、キー配列の違いと見られる（推定） | コード |
| 機種コード 4 | 文字読み出しの途中から末尾のパッチ域へ飛ぶ（6.4 `F1BCDh` → `FFEB7h`） | コード |
| 機種コード 4 | リセット時、`($D9)` が 3 のとき `[BFCC9h]` に `F2158h` を入れるなどの初期化を追加（6.4 `F1621h`〜） | コード |

### 3.4 FUNC 装置の表示（機種コード 1・4）

[ROM_VERSIONS_DRIVERS.md](ROM_VERSIONS_DRIVERS.md) §3.2 の行列演算の追加機能に合わせて、表示処理（6.2 `E178Eh`〜`E1BB0h`、6.4 `E1886h`〜`E1C4Fh`）にも `[BFEE3h]` の値による分岐、表示桁数・行数の定数の違い（`A=02h`→`08h`、`06h`→`0Ch` など）、`BFF28h`・`BFF30h` の作業域を使う処理が加わっている。確度: コード。

### 3.5 PC-1480U（2.1）

2.1 は IOCS 主処理（`E002Ah` 付近）、SYSTM:、FCS（`E090Ch`〜`E0DD9h`）、RAM ディスク（`E4AE5h`〜`E4FC1h`）、RAM カード S1:（`F0004h`〜`F0B27h`）、キーボード（`F161Fh`〜`F1BABh`）、画面（`F289Ah`〜`F2B33h`）、行エディタの各所で 2.2 と違い、この帯だけで約 150 か所ある。同じ改訂 2 でも、128 KB の ROM に収めるための別構成になっている。個々の違いは調べていない。

## 5. 調べ方

[ROM_VERSIONS_BASIC.md](ROM_VERSIONS_BASIC.md) §7 と同じ方法に、次を加えた。

- 呼出し元の逆引きの名札に、ROM 8.5 の IOCS・FCS のコマンド入口（[IOCS_REFERENCE.md](IOCS_REFERENCE.md)）と、リセット・割込みのベクタを使った。8.5 の番地を、命令列の対応から各 ROM の番地へ写している。
- IOCS ヘッダは、文字列 `STDO:SCRN:` の 8 バイト前を先頭として連結をたどった。
- フォントは、`BFC84h` へ写すポインタ表（`MV Y,BFC84h` / `MV X,表` / `MV IL,12h` の並び）から本体の番地を求め、256 文字×6 バイトを比べた。
- 画面の文言は、エミュレータで電源を入れた直後の液晶を読み取って比べた。
