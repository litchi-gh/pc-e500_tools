# PC-E500 シリーズ ROM 版ごとの違い：ROM マップ

手元の ROM イメージ 11 本（`Emulator/app/rom/`）について、ROM の配置と主な番地を比べた資料です。機械語から ROM を呼ぶときや、ROM を読むときに使います。

| 関連する内容 | 資料 |
|---|---|
| 版番号の読み方、BASIC の違い | [ROM_VERSIONS_BASIC.md](ROM_VERSIONS_BASIC.md) |
| IOCS、表示、キー入力のコードの違い | [ROM_VERSIONS_SYSTEM.md](ROM_VERSIONS_SYSTEM.md) |
| 行列演算、周辺機器のドライバの違い | [ROM_VERSIONS_DRIVERS.md](ROM_VERSIONS_DRIVERS.md) |
| 言語、カナ、G: ドライブの違い | [ROM_VERSIONS_MODELS.md](ROM_VERSIONS_MODELS.md) §3 |

## 確度の表し方

| 表記 | 意味 |
|---|---|
| **データ** | ROM のファイルから読み取った |
| **実験** | エミュレータで全 ROM を起動し、RAM の値を読んだ。内蔵 RAM は 64 KB |
| **コード** | 逆アセンブルを読んだ |

特に断らない値はデータです。

## 1. イメージの形

| ROM | ファイルの大きさ | 中身 |
|---|---|---|
| 2.1（PC-1480U） | 256 KB | 実体 128 KB を 2 回並べたもの。前半と後半は全バイト同じ。`C0000h` 以降に置くと `E0000h`〜`FFFFFh` が実体 |
| 2.2、3.2、5.3、6.3、6.2、7.2（PC-E500、PC-E500PJ）、7.5（PC-E550）、6.4（PC-1490UII） | 256 KB | `C0000h`〜`FFFFFh` の本体 ROM |
| 8.4（PC-U6000）、8.5（PC-E650） | 384 KB | 先頭 128 KB が拡張 ROM（`20000h`〜`3FFFFh`）、続く 256 KB が本体 ROM（`C0000h`〜`FFFFFh`） |

384 KB のイメージは、ファイルの位置と CPU の番地が連続していません。ファイル位置 `20000h` が番地 `C0000h` です。

## 2. 帯ごとの同一性

同じ縦棒の区切りの中の版は、その帯が全バイト同じです。2.1 はどの帯も単独です。

| 帯 | 内容 | 同じ版の組 |
|---|---|---|
| `C0000h`〜`C0017h` | ROM の先頭（スロットの管理情報） | 2.2 ｜ 3.2、5.3、6.3、6.2、7.2、7.5、8.5 ｜ 6.4、8.4 |
| `C0018h`〜`DF7FFh` | G: の領域 | 2.2、3.2、6.2、7.2 ｜ 5.3、6.3 ｜ 7.5、8.5 ｜ 6.4 ｜ 8.4 |
| `DF800h`〜`DFCFFh` | IOCS ヘッダなど | 6.2、7.2、7.5 ｜ ほかは各版で単独 |
| `DFD00h`〜`DFFFFh` | 第 2 のフォント | 2.2、3.2、5.3、6.3、6.2、7.2、7.5、8.5 ｜ 6.4 ｜ 8.4 |
| `E0000h`〜`EFFFFh` | IOCS、装置ドライバ | 7.2、7.5 ｜ ほかは各版で単独 |
| `F0000h`〜`FFFFFh` | 起動、表示、キー入力、BASIC | 全版で単独 |

`C0000h` の先頭の 3 バイトは、2.2 が `02 02 40`、3.2、5.3、6.3、6.2、7.2、7.5、8.5 が `10 12 40`、6.4 と 8.4 が `10 12 3E` です。3.2 のリセットの処理は、このうち `10 12` をスロットの印として調べます（[SYSTEM_INTERNALS.md](SYSTEM_INTERNALS.md) §2）。

## 3. 公開入口とベクタ

呼ぶ番地は全版で同じです。飛び先が版で変わるので、機械語からは次の番地を呼び、飛び先を直接呼ばないようにします。

| 版 | `FFFD8h` 作業領域 | `FFFDCh` Function | `FFFE4h` FCS | `FFFE8h` IOCS | `FFFFAh` 割込み | `FFFFDh` リセット |
|---|---|---|---|---|---|---|
| 2.1 | `F99BCh` | `EF378h` | `E092Fh` | `F33B8h` | `F1F56h` | `F1031h` |
| 2.2 | `F9D1Eh` | `EF383h` | `E06BFh` | `E0000h` | `F1FF8h` | `F10BDh` |
| 3.2 | `F9D31h` | `EF2EEh` | `E06BFh` | `E0000h` | `F2005h` | `F10BDh` |
| 5.3 | `F9CC0h` | `EF2D9h` | `E06BFh` | `E0000h` | `F1FB5h` | `F10C2h` |
| 6.3 | `F9CC0h` | `EF2DFh` | `E06BFh` | `E0000h` | `F1FB5h` | `F10C2h` |
| 6.2、7.2、7.5 | `F9D31h` | `EF2F4h` | `E06BFh` | `E0000h` | `F2005h` | `F10BDh` |
| 6.4 | `F9B94h` | `EF317h` | `E06BFh` | `E0000h` | `F2035h` | `F10BDh` |
| 8.4 | `F951Ch` | `EF03Eh` | `E06BFh` | `E0000h` | `F20C3h` | `F10BEh` |
| 8.5 | `F96C8h` | `EF02Fh` | `E06BFh` | `E0000h` | `F209Bh` | `F10BEh` |

入口はどれも `JPF`（`03h`）です。2.1 の `FFFE8h` だけが `JP`（`02h`）で同じセグメントの `F33B8h` へ飛びます。

### 3.1 末尾のバイト

`FFFF0h`、`FFFF1h` は版番号です。公開入口の間と版番号の後ろの埋め方は版で違います。

| 版 | 使わないバイト | `FFFECh`〜`FFFEFh` | `FFFF2h`〜 |
|---|---|---|---|
| 2.1、2.2、3.2、8.4、8.5 | `FFh` | `FF FF FF FF` | `FF`… |
| 5.3 | `00 00 FF FF` | `00 00 F8 58` | `00 00 FF FF 00 00 FF FF` |
| 6.3 | `00 00 FF FF` | `00 00 F8 7E` | `00 00 FF FF 00 00 FF FF` |
| 6.4 | `00 00 FF FF` | `00 00 FA 7E` | `00 00 FF FF 00 00 FF FF` |
| 6.2、7.5 | `9Fh` | `9F 9F 9F 9F` | `9F`… |
| 7.2 | `9Fh` | `9F 9F 9F 9F` | `77 9F 9F`… |

5.3、6.3、6.4 の `FFFEEh`、`FFFEFh` と、7.2 の `FFFF2h` の `77h` の意味は分かっていません。

## 4. IOCS

### 4.1 ヘッダの場所

ヘッダの先頭は `BFCA2h` に入ります（実験）。全版とも 10 個の装置が同じ順で連結しています。

| 版 | 先頭 | 最後のヘッダ |
|---|---|---|
| 2.1 | `E02A6h` | `E032Fh` |
| 2.2、3.2、5.3、6.3、6.2、7.2、7.5、8.5 | `DF820h` | `DF8A9h` |
| 6.4、8.4 | `DF500h` | `DF589h` |

名前と属性も全版で同じです。例外は 2.1 で、`COM:` の属性が `C3h`（ほかは `D3h`）、`CAS:` の属性が `C7h`（ほかは `D7h`）です。

## 5. フォント

BASIC を起動した後の `BFC84h`〜`BFC95h` のポインタです（実験）。文字コードとの対応は [MEMORY.md](MEMORY.md) §8 にあります。

| 版 | `BFC84h` | `BFC87h` 00h〜 | `BFC8Ah` 80h〜 | `BFC8Dh` E0h〜 | `BFC90h` 20h〜 | `BFC93h` A0h〜 |
|---|---|---|---|---|---|---|
| 2.1 | `F288E` | `F20F6` | `F23F6` | `F2636` | `F21B6` | `F24B6` |
| 2.2 | `F2930` | `F2198` | `F2498` | `F26D8` | `F2258` | `F2558` |
| 3.2、6.2、7.2、7.5 | `F293D` | `F21A5` | `F24A5` | `F26E5` | `F2265` | `F2565` |
| 5.3、6.3 | `F28ED` | `F2155` | `F2455` | `F2695` | `F2215` | `F2515` |
| 6.4 | `F296D` | `F21D5` | `F24D5` | `F2715` | `F2295` | `F2595` |
| 8.4、8.5 | `30798` | `30000` | `30300` | `30540` | `300C0` | `303C0` |

**8.x だけ、フォントが拡張 ROM にあります。**

第 2 のフォント（`DFD00h`〜`DFFFFh`）は、形式 A の G: を持つ版の帯にあります（§2）。6.4 と 8.4 の同じ帯は別の内容です。欧州版がこの番地を文字セットの切替えに使います（[MEMORY.md](MEMORY.md) §8）。

フォントの違いの内容は [ROM_VERSIONS_SYSTEM.md](ROM_VERSIONS_SYSTEM.md) §3.1 にあります。

### 6.2 作業領域のポインタ

## 7. BASIC の表

処理表と辞書の番地は [ROM_VERSIONS_BASIC.md](ROM_VERSIONS_BASIC.md) §1 にあります。8.4 と 8.5 だけキーワードが 168 語で、ほかは 159 語です。

## 8. 使っていない領域

本体 ROM の中で、同じ値が 256 バイト以上続く範囲です。

| 版 | 範囲と値 |
|---|---|
| 2.1 | なし |
| 2.2、3.2、5.3、6.3、6.2、7.2、7.5 | `C1364h`〜`C1497h`（`00h`。G: のルートの未使用部分） |
| 6.4 | `C05F6h`〜`C0B17h`（`00h`）、`DADFFh`〜`DB7FFh`（`9Fh`）、`DF1DAh`〜`DF4FFh`（`9Fh`） |
| 8.4 | 6.4 と同じ 3 か所、`EFCAEh`〜`EFEFFh`（`FFh`）、`FFB4Dh`〜`FFEFFh`（`FFh`） |
| 8.5 | `C1364h`〜`C1497h`（`00h`）、`EFCE7h`〜`EFFFFh`（`FFh`）、`FFC4Dh`〜`FFFD7h`（`FFh`） |

8.x は本体 ROM の `E` と `F` のセグメントの末尾に空きがあります。フォントを拡張 ROM へ移した分と見られます（推定）。

## 9. 拡張 ROM（8.4、8.5）

### 9.1 配置

| 範囲 | 内容 | 8.4 と 8.5 |
|---|---|---|
| `20000h`〜`2FFFFh` | 全バイト `FFh` | 同じ |
| `30000h`〜`305FFh` | 6×8 ドットのフォント 256 文字 | 同じ |
| `30600h`〜 | `30798h` からのドット列（`BFC84h` が指す）、BASIC のエラーメッセージ、拡張の処理など | 下の差分 |
| 終わり | 8.4 は `339D9h`、8.5 は `33A18h` まで。後ろは `FFh` | |

### 9.2 8.4 と 8.5 の差

データがある範囲（8.4 で 14,810 バイト）のうち、14,226 バイトは位置をずらせば一致します。残りは次のとおりです。

| 違い | 内容 |
|---|---|
| 1〜2 バイトの置き換え（496 か所） | 本体 ROM の番地が版で違うためと見られる（`CALLF` の飛び先など。推定） |
| 機種名の文字列 | `PC-U6000  Ver.XX` と `PC-E650   Ver.XX` |
| 長さの変わる違い（4 か所） | 8.4 の `31D72h` 付近、`32D8Ch`、`331ECh` 付近、`339DAh`（末尾）に当たる位置で、8.5 のバイトが増えている |

5 文字以上の文字列は、この機種名の 1 本を除いて同じです（共通 163 本）。8.5 で増えたバイトの役割は調べていません。

`KEY Menu`、`Ful key check` などの文字列は診断メニューのものです（[ROM_VERSIONS_SYSTEM.md](ROM_VERSIONS_SYSTEM.md) §2.4）。

## 10. G: ドライブ

形式と構造の違いは [ROM_VERSIONS_MODELS.md](ROM_VERSIONS_MODELS.md) §3 にあります。番地の要点は次のとおりです。

| 項目 | 形式 A（2.2、3.2、5.3、6.3、6.2、7.2、7.5、8.5） | 形式 B（6.4、8.4） | なし（2.1） |
|---|---|---|---|
| ブロックの先頭 | `C0018h` | `C0018h` | |
| FAT | `C0058h` | `C0118h` | |
| ルート | `C0BD8h` | `C0318h` | |
| データ | `C1498h` | `C0B18h` | |
| 使っている最後の番地 | `DF5D7h` | `CD517h` | |
| 続く領域 | `DF800h` から IOCS ヘッダ | GRAPH の機械語など | |

2.1 は `C0000h`〜`DFFFFh` に `E0000h`〜`FFFFFh` の写しが見えるイメージです（§1）。

## 11. カードの処理

動きはどの版も同じです（[CARD_SLOT.md](CARD_SLOT.md) §12）。違うのは番地と次の点です。表示は 5.3 と 6.3 が英語、ほかは日本語です。

| 版 | 書込みテスト | 容量の測定 | ヘッダを書く | `RESET.KEY` を探す | `S3:` の場所 |
|---|---|---|---|---|---|
| 2.1 | `F0B85h` | `F0E4Fh` | `F0D8Eh` | `F0FE6h` | `10000h` |
| 2.2、3.2、6.2、6.4、7.2、7.5 | `F0C11h` | `F0EDBh` | `F0E1Ah` | `F1072h` | `C0000h` |
| 5.3、6.3 | `F0C11h` | `F0EE0h` | `F0E1Fh` | `F1077h` | `C0000h` |
| 8.4、8.5 | `F0C11h` | `F0EDBh` | `F0E1Ah` | `F1073h` | `C0000h` |

2.1 には ROM の G: がなく（§10）、`S3:` は `10000h` を調べます。

## 12. 調べ方

- ROM のファイルを Python で読み、§1〜§4、§8〜§10 の値を取り出しました。
- IOCS ヘッダは、文字列 `STDO:SCRN:` の 8 バイト前を先頭として連結をたどりました。
- §5、§6 は、エミュレータで全 ROM を起動してメインメニューから BASIC に入り、RAM を読みました。
- §9.2 は、データのある範囲を差分のアルゴリズムで並べて比べました。
- §11 は、5.3 の処理と同じバイト列の位置を各版で確かめ、動きはエミュレータで試しました。
- コードの比較の方法は [ROM_VERSIONS_BASIC.md](ROM_VERSIONS_BASIC.md) §7 にあります。
