# ROM マップと主要入口

手元の ROM イメージ全 11 本（`Emulator/app/rom/`）の領域と主な番地をまとめた資料です。領域の並びは全版でほぼ共通で、番地が版によって変わります。

| 関連する内容 | 資料 |
|---|---|
| IOCS の装置の入口、割込みのベクタ、未使用領域、版ごとの同一性 | [ROM_VERSIONS_MAP.md](ROM_VERSIONS_MAP.md) |
| 版番号の読み方、BASIC の違い | [ROM_VERSIONS_BASIC.md](ROM_VERSIONS_BASIC.md) |
| G: ドライブの形式 | [ROM_VERSIONS_MODELS.md](ROM_VERSIONS_MODELS.md) §3 |

## 1. 対象と物理配置

| 版 | 機種 | ファイルの長さ | 配置 |
|---|---|---|---|
| 2.1 | PC-1480U | 256 KB | 実体 128 KB を 2 回並べたもの。`E0000h`〜`FFFFFh` が実体で、`C0000h`〜`DFFFFh` はその写し |
| 2.2、3.2、5.3、6.3、7.2 | PC-E500 | 256 KB | `C0000h`〜`FFFFFh` の本体 ROM |
| 6.2 | PC-E500PJ | 256 KB | 同上 |
| 6.4 | PC-1490UII | 256 KB | 同上 |
| 7.5 | PC-E550 | 256 KB | 同上 |
| 8.4 | PC-U6000 | 384 KB | 先頭 128 KB が拡張 ROM（`20000h`〜`3FFFFh`）、続く 256 KB が本体 ROM |
| 8.5 | PC-E650 | 384 KB | 同上 |

384 KB のイメージは、ファイルの位置と CPU の番地が連続していません。ファイル位置 `20000h` が番地 `C0000h` です。

## 2. 領域の並び

2.1 を除く本体 ROM の並びです。番地が版で変わるものは §4、§5 に版ごとの値があります。

| 範囲 | 内容 | 版による違い |
|---|---|---|
| `C0000h`〜`C0017h` | スロットの管理情報 | 先頭 3 バイトが 3 通り（[ROM_VERSIONS_MAP.md](ROM_VERSIONS_MAP.md) §2） |
| `C0018h`〜 | G: の `RAMFILE` ブロック（ROM に焼かれた読出し用イメージ） | 形式 A と形式 B で中の配置が違う（§6） |
| `DF500h`、`DF820h` | IOCS ヘッダの連結リスト | 6.4、8.4 が `DF500h`、ほかが `DF820h` |
| `DFD00h`〜`DFFFFh` | 第 2 の 6×8 ドット群 | 形式 A の版だけ（§6） |
| `E0000h`〜 | IOCS、FCS、装置ドライバ | |
| `E493Ah` 付近 | RAM ディスク、メモリブロックの制御 | 版で前後する |
| `EF000h` 付近 | Function ドライバ | 版で前後する |
| `F0000h`〜 | リセット、割込み、表示、キー入力、BASIC | |
| `FFFD8h`〜`FFFFFh` | 公開入口、ベクタ、版番号 | 番地は全版で同じ |

2.1 は `E0000h`〜`FFFFFh` に同じ種類の領域が入り、IOCS のメインは `F33B8h` にあります。G: と第 2 のドット群はありません。

## 3. 固定入口

呼ぶ番地は全版で同じです。飛び先が版で変わるので、機械語からは左の番地を呼びます。入口はどれも `JPF` で、2.1 の `FFFE8h` だけが `JP` です。`FFFFAh`、`FFFFDh` はベクタです。

| 版 | `FFFD8h` 補助 | `FFFDCh` Function | `FFFE4h` FCS | `FFFE8h` IOCS | `FFFFAh` 割込み | `FFFFDh` リセット |
|---|---|---|---|---|---|---|
| 2.1 | `F99BCh` | `EF378h` | `E092Fh` | `F33B8h` | `F1F56h` | `F1031h` |
| 2.2 | `F9D1Eh` | `EF383h` | `E06BFh` | `E0000h` | `F1FF8h` | `F10BDh` |
| 3.2 | `F9D31h` | `EF2EEh` | `E06BFh` | `E0000h` | `F2005h` | `F10BDh` |
| 5.3 | `F9CC0h` | `EF2D9h` | `E06BFh` | `E0000h` | `F1FB5h` | `F10C2h` |
| 6.3 | `F9CC0h` | `EF2DFh` | `E06BFh` | `E0000h` | `F1FB5h` | `F10C2h` |
| 6.2、7.2、7.5 | `F9D31h` | `EF2F4h` | `E06BFh` | `E0000h` | `F2005h` | `F10BDh` |
| 6.4 | `F9B94h` | `EF317h` | `E06BFh` | `E0000h` | `F2035h` | `F10BDh` |
| 8.4 | `F951Ch` | `EF03Eh` | `E06BFh` | `E0000h` | `F20C3h` | `F10BEh` |
| 8.5 | `F96C8h` | `EF02Fh` | `E06BFh` | `E0000h` | `F209Bh` | `F10BEh` |

`FFFD8h` は機械語エリアの確保などに使う公開補助入口（既存利用例あり）、`FFFF0h`、`FFFF1h` は版番号です。

## 4. システムの領域

| 版 | IOCS ヘッダ | RAM ディスク制御 | 文字ドット選択 | 文字 256 字 |
|---|---|---|---|---|
| 2.1 | `E02A6h`〜`E033Eh` | `E4A83h`〜`E4D67h` | `F2A9Eh`〜`F2B76h` | `F20F6h`〜`F26F5h` |
| 2.2 | `DF820h`〜`DF8B8h` | `E493Ah`〜`E4C69h` | `F2B42h`〜`F2C4Eh` | `F2198h`〜`F2797h` |
| 3.2、6.2、7.2、7.5 | `DF820h`〜`DF8B8h` | `E493Ah`〜`E4C69h` | `F2B4Fh`〜`F2C5Bh` | `F21A5h`〜`F27A4h` |
| 5.3、6.3 | `DF820h`〜`DF8B8h` | `E493Eh`〜`E4C6Dh` | `F2AFFh`〜`F2C0Bh` | `F2155h`〜`F2754h` |
| 6.4 | `DF500h`〜`DF598h` | `E4910h`〜`E4C3Fh` | `F2B7Fh`〜`F2C8Bh` | `F21D5h`〜`F27D4h` |
| 8.4 | `DF500h`〜`DF598h` | `E4910h`〜`E4C3Fh` | `F246Dh`〜`F2579h` | `30000h`〜`305FFh` |
| 8.5 | `DF820h`〜`DF8B8h` | `E493Ah`〜`E4C69h` | `F2445h`〜`F2551h` | `30000h`〜`305FFh` |

- **IOCS ヘッダ:** 全版とも 10 個が連結しています。`BFCA2h` が先頭を指します。
- **RAM ディスク制御:** 先頭は IOCS 装置 5 の入口です。
- **文字ドット選択:** 文字コードの帯ごとの分岐と、`BFC84h`〜`BFC95h` へのポインタの設定をします。
- **文字 256 字:** 1 字 6 バイトで、`BFC87h` がこの先頭を指します。**8.x だけ拡張 ROM にあります。** 5.3、6.3 以外は全バイト同じで、5.3、6.3 は英語版の文字セットです（[ROM_VERSIONS_SYSTEM.md](ROM_VERSIONS_SYSTEM.md) §3.1）。

| 版 | 代替ドット列（`BFC84h`） | その参照 | `C0018h` を見る所 |
|---|---|---|---|
| 2.1 | `F288Eh` | `F2C37h` | なし |
| 2.2 | `F2930h` | `F2CE4h` | `E4BE8h` |
| 3.2、6.2、7.2、7.5 | `F293Dh` | `F2CF1h` | `E4BE8h` |
| 5.3、6.3 | `F28EDh` | `F2CA1h` | `E4BECh` |
| 6.4 | `F296Dh` | `F2D21h` | `E4BBEh` |
| 8.4 | `30798h` | `F260Fh` | `E4BBEh` |
| 8.5 | `30798h` | `F25E7h` | `E4BE8h` |

`C0018h` を見る所は、G: のときにメモリブロックの先頭を固定で参照する処理です。

## 5. BASIC の領域

| 版 | トークン逆引き | 処理レコード | キーワード辞書 | 語数 | 中間コードの処理 |
|---|---|---|---|---|---|
| 2.1 | `F53D0h`〜`F55CFh` | `F55D0h`〜`F58CFh` | `F58DBh`〜`F5CC3h` | 159 | `F5CC4h`〜 |
| 2.2 | `F55CFh`〜`F57CEh` | `F57CFh`〜`F5ACEh` | `F5ADAh`〜`F5EC2h` | 159 | `F5EC3h`〜 |
| 3.2、6.2、7.2、7.5 | `F55D1h`〜`F57D0h` | `F57D1h`〜`F5AD0h` | `F5ADCh`〜`F5EC4h` | 159 | `F5EC5h`〜 |
| 5.3、6.3 | `F5581h`〜`F5780h` | `F5781h`〜`F5A80h` | `F5A8Ch`〜`F5E74h` | 159 | `F5E75h`〜 |
| 6.4 | `F5601h`〜`F5800h` | `F5801h`〜`F5B00h` | `F5B0Ch`〜`F5EF4h` | 159 | `F5EF5h`〜 |
| 8.4 | `F4E4Ch`〜`F504Bh` | `F504Ch`〜`F534Bh` | `F5357h`〜`F5785h` | 168 | `F5786h`〜 |
| 8.5 | `F4E29h`〜`F5028h` | `F5029h`〜`F5328h` | `F5334h`〜`F5762h` | 168 | `F5763h`〜 |

- **トークン逆引き:** 16 bit の項目が 256 個並びます。
- **処理レコード:** `token × 3` で引く 3 バイトの表です。直後の 11 バイトのポインタを挟んでキーワード辞書が続きます。
- **キーワード辞書:** `[長さ][ASCII 名][token]` の並びで、頭文字ごとに `00h` で区切ります。語のない頭文字は `00h` だけです。
- **中間コードの処理:** 辞書の直後から、トークンの分類と処理入口の選択が続きます。

| 版 | 逆引きを使う所 | 処理レコードを引く所 |
|---|---|---|
| 2.1 | `F4EE0h` | `F5E4Ch`、`F5E7Fh` |
| 2.2 | `F50DFh` | `F604Bh`、`F607Eh` |
| 3.2、6.2、7.2、7.5 | `F50E1h` | `F604Dh`、`F6080h` |
| 5.3、6.3 | `F5091h` | `F5FFDh`、`F6030h` |
| 6.4 | `F5111h` | `F607Dh`、`F60B0h` |
| 8.4 | `F495Ch` | `F5953h`、`F5986h` |
| 8.5 | `F4939h` | `F5930h`、`F5963h` |

## 6. G: と第 2 のドット群

| 版 | G: の形式 | `C0018h` のブロック | 第 2 のドット群（`DFD00h`〜`DFFFFh`） |
|---|---|---|---|
| 2.2、3.2、5.3、6.3、6.2、7.2、7.5、8.5 | 形式 A | `RAMFILE`。FAT `C0058h`、ルート `C0BD8h`、データ `C1498h`、最後 `DF5D7h` | あり。8 本とも全バイト同じ |
| 6.4、8.4 | 形式 B | `RAMFILE`。FAT `C0118h`、ルート `C0318h`、データ `C0B18h`、最後 `CD517h` | なし。この帯は別の内容 |
| 2.1 | なし | | なし |

第 2 のドット群は、通常の文字表示で使う表とは別のもので、欧州版が文字セットの切替えに使います（[MEMORY.md](MEMORY.md) §8）。

## 7. 拡張 ROM（8.4、8.5）

| 範囲 | 内容 |
|---|---|
| `20000h`〜`2FFFFh` | 全バイト `FFh` |
| `30000h`〜`305FFh` | 文字 256 字。8.4 と 8.5 で全バイト同じ |
| `30798h` | 代替、制御文字用のドット列（`BFC84h` が指す） |
| `30600h`〜 | BASIC のエラーメッセージ、拡張の処理など |
| 終わり | 8.4 は `339D9h`、8.5 は `33A18h`。後ろは全バイト `FFh` |

2 本の差は [ROM_VERSIONS_MAP.md](ROM_VERSIONS_MAP.md) §9 にあります。

## 8. RAM 上のポインタ

BASIC を起動した後の値です（エミュレータで全版を起動して読みました）。

| 番地 | 内容 | 値 |
|---|---|---|
| `BFCA2h` | IOCS ヘッダの先頭 | §4 の IOCS ヘッダの先頭 |
| `BFC84h` | 代替ドット列 | §4 の表 |
| `BFC87h` | 文字コード 00h〜 | 文字 256 字の先頭 |
| `BFC8Ah` | 80h〜 | 先頭 + `300h` |
| `BFC8Dh` | E0h〜 | 先頭 + `540h` |
| `BFC90h` | 20h〜 | 先頭 + `C0h` |
| `BFC93h` | A0h〜 | 先頭 + `3C0h` |

## 9. ROM 8.5 のコード到達解析

公開ベクタ、IOCS と FCS の全表、BASIC の全トークン入口、文字の初期化を起点に再帰的に走査し、39,310 個の命令の開始、94,090 バイトを、重複なしで到達可能なコードとして得ました。デコードが止まった所は 0 件です。間接ジャンプの先は入りません。

## 10. 調べ方

- §1、§3、§6、§7 は ROM のファイルから直接読みました。
- IOCS ヘッダは、文字列 `STDO:SCRN:` の 8 バイト前を先頭として連結をたどりました。全版で 10 個です。
- キーワード辞書は頭文字の組を順にたどり、名前にならないバイトを終わりとしました。語数は 159 語（8.x は 168 語）で、[ROM_VERSIONS_BASIC.md](ROM_VERSIONS_BASIC.md) §1 と一致します。
- 文字 256 字は、`BFC87h` の値の位置のバイトを 8.5 の字形と比べました。
- コードの領域と参照の番地は、8.5 の該当のバイト列に最も近い所を各版で探しました。番地を含むバイトは版で変わるので、完全には一致しません。文字ドット選択の終わりは、版による差が大きい部分なので、前の位置からの距離で求めました。
- 8.5 の領域の根拠は、ROM の固定参照と表の構造です。IOCS メインは `FFFE8h` から `JPF`、FCS は `FFFE4h` から `JPF` で `00h`〜`11h` の 18 項目の表を参照します。
