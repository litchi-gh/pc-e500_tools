# 起動、割込み、タイマ、音

電源を入れてから動くまでの処理、割込み、タイマ、ブザーの音をまとめた資料です。レジスタの一覧は [PC-E650_ASSEMBLER_MANUAL.md](PC-E650_ASSEMBLER_MANUAL.md) §1.4 を参照してください。

## 情報源と確度

| 表記 | 情報源 |
|---|---|
| **公式** | PC-E500 Technical Reference Manual（p.48〜49、p.91〜94）、Service Manual |
| **CPU 資料** | ESR-L CPU Technical Manual（[Forth500 の resources](https://github.com/Robert-van-Engelen/Forth500/tree/main/resources) で公開されている PDF。OCR で読んだ） |
| **コード** | ROM 3.2 の逆アセンブル |
| **実験** | エミュレータで測った |

実機では測っていません。

## 1. クロック

| 項目 | 値 | 根拠 |
|---|---|---|
| メインクロック | 2.304 MHz（セラミック発振） | 公式、CPU 資料 |
| 1 実行サイクル | 1.30 µs（クロック 3 周期 = **768 kHz**） | CPU 資料 |
| 別の設定 | 1.536 MHz（1.95 µs）、3.072 MHz（0.98 µs）。CPU の製造時の設定で選ぶ | CPU 資料 |
| サブクロック | CR 発振、標準 40 kHz（表示クロックとタイマ）。水晶なら 32.768 kHz | CPU 資料 |

サイクル数と時間の関係は 768 kHz で換算できます。録音から求めたテープの速度（約 0.77 MHz。[TAPE_FORMAT.md](TAPE_FORMAT.md)）とも一致します。エミュレータは 1.024 MHz（3.072 MHz ÷ 3）で動きます。

## 2. リセットの処理

リセットベクタは `FFFFDh` にあります。3.2 は `F10BDh`、8.5 は `F10BEh` です。処理の流れは次のとおりです（コード、3.2）。

| 順 | 番地 | 内容 |
|---|---|---|
| 1 | `F10BDh` | `IMR` を 0 にして割込みを止める |
| 2 | `F10C5h` | LCD の表示を止める（`0A000h` に `3Eh`） |
| 3 | `F10CFh` | ON キーの状態を確かめる（`SSR` ビット 3 をくり返し読む） |
| 4 | `F10F8h` | `SCR`（`FDh`）を 02h にする |
| 5 | `F1106h` | キーの 1 行を読み、押されていれば別の処理（`F100Ah`）へ |
| 6 | `F1120h` | 電池の検出を有効にして（E3）、電池切れなら `F100Ah` へ |
| 7 | `F114Ch` | 表示の電源を入れる（E4） |
| 8 | `F1150h` | ON キーが離されるのを待つ |
| 9 | `F1160h` | `BE000h` に `5AA5h` を書いて RAM を確かめる |
| 10 | `F1178h` | `BP`、`U`=`BFC6Dh`、`S`=`BFC90h`、`E6h`=`BFCDEh` などを設定する |
| 11 | `F119Ah` | 割込みベクタの一部を設定する |
| 12 | `F11C4h` | `C0000h` のスロットの印（`10 12`）を確かめる |
| 13 | `F11EAh` | `10000h`（ROM カード）と `40000h`（RAM カード）を確かめる |

カードが新しいと `S2(CARD):NEW CARD` を表示します（[PERIPHERALS.md](PERIPHERALS.md) §7.3）。内蔵 RAM が初期化されていないと `S1` についても同じ表示が出て、PF1 だけが選べます（実験）。

## 3. 割込み

### 3.1 要因

CPU の割込みベクタは `FFFFAh` の 1 つだけで、ROM が要因を調べて RAM のベクタへ飛びます（公式 p.91、コード）。

| ビット | 要因 | RAM のベクタ | ROM 3.2 の値 | 用途（公式） |
|---|---|---|---|---|
| 0 | 速いタイマ | `BFCC6h` | `F20C4h` | BREAK キーを含むキースキャン |
| 1 | 遅いタイマ | `BFCC9h` | `F215Ch` | カーソルの点滅など |
| 2 | キー | `BFCCCh` | `F20B1h` | 未使用 |
| 3 | ON キー | `BFCCFh` | `F20BAh` | 未使用 |
| 4 | シリアル送信 | `BFCD2h` | `F20C3h` | 未使用 |
| 5 | シリアル受信 | `BFCD5h` | `F614Ch` | 受信 |
| 6 | 外部 | `BFCD8h` | `F20DFh` | 電池の検出 |
| 7 | ソフトウェア | `BFCDBh` | `F20C3h` | 未使用 |

ベクタは RAM にあるので書き換えられます。ソフトウェア割込みのベクタは、ROM のコードが `BFCDBh` を読むことで確かめました（`F2091h`）。

### 3.2 レジスタ

| 内部 RAM | 名前 | 内容 |
|---|---|---|
| `FCh` | ISR | 要因。1 で要求 |
| `FBh` | IMR | 許可。1 で許可。ビット 7 は全体の許可 |
| `EBh` | IISR | 処理中の要因。ビット 7 はソフトウェア割込み |

### 3.3 優先順位

ROM の入口（3.2 `F2005h`）は、次の順に要因を調べます（コード）。

**受信 → 外部 → 送信 → ON キー → キー → 遅いタイマ → 速いタイマ → ソフトウェア**

どの要因にも当たらなければ、戻り先の 1 バイトが `FEh`（`IR` 命令）かどうかを調べ、そうならソフトウェア割込みとして扱います。

### 3.4 割込みの処理を書くときの注意（公式 p.92）

- `RETF` で終わる
- U スタックと S スタックを多く使わない（数十バイトまで）
- 内部 RAM は退避して、元に戻す
- 表示の処理と重ならないようにする

## 4. タイマ

| タイマ | 周期 | 選択 | 根拠 |
|---|---|---|---|
| 速いタイマ | 4 ms か 16 ms（通常 16 ms） | `SCR` ビット 1。0 で 4 ms | 公式 |
| 遅いタイマ | 約 0.5 秒か約 2 秒（通常約 0.5 秒） | `SCR` ビット 2。0 で約 0.5 秒 | 公式 |

速いタイマは CPU のクロックを分周するので、`HALT` と `OFF` の間は止まります。遅いタイマはサブクロックを分周するので、`OFF` の間だけ止まり、周期は電源電圧でかなり変わります（公式）。

テープの入出力の処理は、速いタイマの周期を 4 ms に切り替えます（コード）。

## 5. システム制御（SCR、FDh）

| ビット | 名前 | 内容 |
|---|---|---|
| 7 | ISE | 外部割込みで `HALT` / `OFF` から戻る |
| 6〜4 | BZ2〜BZ0 | CO と CI のピン（下の表） |
| 3 | VDDC | 表示電源。SC62015B01 では 1 にするとサブクロックも止まる |
| 2 | STS | 遅いタイマの選択 |
| 1 | MTS | 速いタイマの選択 |
| 0 | DISC | 表示の制御 |

| BZ2〜0 | CO の出力 | CI の入力 |
|---|---|---|
| 000 | Low | 使わない |
| 001 | High | 使わない |
| 010 | 2 kHz | 使わない |
| 011 | 4 kHz | 使わない |
| 100 | Low | 使う |
| 101 | High | 使う |
| 11x | CI と同じ | 使う |

（CPU 資料。OCR の表なので確度は高くありません。）

テープの読み込みが BZ を 111 にしているのは、テープの音をそのままブザーへ返すためです。

## 5.1 システム状態（SSR、FFh）

読出し専用です（CPU 資料）。

| ビット | 名前 | 内容 |
|---|---|---|
| 3 | ONK | ON ピンの状態。ROM はこれで `BREAK` を調べる |
| 2 | RSF | RESET が High で 0、HALT / OFF で 1 |
| 1 | CI | テープの入力ピンの状態 |
| 0 | TEST | TEST ピンの状態 |

## 6. 音（BEEP）

ROM の `BEEP` は 2 kHz と 4 kHz の設定を使わず、ソフトウェアで CO を切り替えます。`BEEP n,P,D` の 1 周期のサイクル数は次のとおりです（実験）。

```text
周期 = 270 + 12 × P サイクル
```

| P | サイクル | 周波数（768 kHz） |
|---|---|---|
| 0 | 270 | 2844 Hz |
| 1 | 282 | 2723 Hz |
| 10 | 390 | 1969 Hz |
| 100 | 1470 | 522 Hz |
| 255 | 3330 | 231 Hz |

`D` は周期の数です。`BEEP 1,0,1000` は 1000 周期でした（実験）。時間は周期によって変わります。

CO は 1 ビットの出力ですが、切り替えの時間を分けて 3 音を同時に鳴らすソフトウェア（PLAY3）が知られています（[EXTERNAL_RESOURCES.md](EXTERNAL_RESOURCES.md)）。

## 7. 自動電源オフ

| 項目 | 内容 | 根拠 |
|---|---|---|
| 時間 | 約 11 分 | マニュアル |
| カウンタ | `[E6h]+06h`。遅いタイマのたびに 1 減らす（3.2 `F2192h`） | コード |
| 初期値 | `BFCBCh` の値（2 バイト、単位は約 0.5 秒）。起動直後は 04B0h（1200） | 公式 p.48、実験 |
| エミュレータ | 放置すると 600 秒で電源が切れた（0.5 秒 × 1200） | 実験 |

マニュアルの約 11 分とエミュレータの 10 分の差は、実機の遅いタイマが 0.5 秒ちょうどではないためと見られます。

公式に `BFCBCh` が自動電源オフの設定として載っています。`POKE &BFCBC,&78,0` で値が変わることは確かめましたが、電源が切れるまでの時間は測っていません。

## 8. 電池の検出

電池の検出回路はサービスマニュアルに説明があります。

| 項目 | 内容 |
|---|---|
| 検出 IC | MN1280 |
| 表示 | CAU レベルで `BATT` を表示、STOP レベルで消える |
| CAU レベル | VCC - GND が 4.2〜4.6 V |
| STOP レベル | VCC - GND が 3.8〜4.2 V |
| 方法 | CPU の E3 を Low にして IRQ を見る。E3 を Hi-Z にして再度見る |
| STOP のあと | ON キーと RESET が効かなくなる |

割込みでは `ISR` のビット 6 で分かります。テープとシリアルの処理は、ループの中でこのビットを調べます（[TAPE_FORMAT.md](TAPE_FORMAT.md)、[SERIAL_PORT.md](SERIAL_PORT.md)）。

## 9. キー入力の流れ

キーが押されてからプログラムが受け取るまでです（公式 p.48〜49）。

```text
タイマ割込み    ハードコードをマトリクスコードへ変換（表は [BFCC0h]）
    |
キースキャンバッファ（16 文字）
    |  [BFCC3h] のフック
IOCS 41h、42h で読み出す
    |  CTRL、SHIFT、HYP、2nd の処理
    |  カナの処理
    |  [BFC41h] のフック
    |  CAPS、FUNCKEY の処理
キーボードバッファ（32 文字）
    |
FCS
    |
ユーザーのプログラム
```

表の番地 `BFCC0h` を差し替えるとキーの配置を変えられます（公式）。本リポジトリでは試していません。関係する番地は [MEMORY_AND_FILES.md](MEMORY_AND_FILES.md) §8 にあります。
